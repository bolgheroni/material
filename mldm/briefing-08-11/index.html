08 · Classification, validation, entropy

5 min

Know cold

  • Classifier = decision function M(x, θ) = y_pred. Learning = find the parameters θ that minimise prediction error on labelled data. It can be crisp (one label) or probabilistic (one probability per class).
  • Training error is optimistic (a lookup table scores 0%). Generalization error on new data is what matters. More flexibility always lowers training error.
  • Underfitting: too simple, high train and test error. Overfitting: learns noise, low train error, much higher test error. Aim for the simplest model that captures the pattern.
  • Train/test split (80-20, 67-33, 50-50). The test set is the future: never learn from it, never choose by looking at it.
  • k-fold cross-validation: k folds, each used once as test, report mean and std of the k errors.
  • Baseline = majority-class rule. NordicMart: "nobody churns" is right 88% of the time. Iris (3 balanced classes): 33%. A model is interesting only if it beats the baseline.
  • VC dimension of a straight line in the plane is 3 (shattering power of a model).

Entropy and information gain (the part to be able to compute)

H(X) = − Σ p_j · log2(p_j) max = log2(V); binary: p=0.5 → 1 bit, p=0 or 1 → 0 IG(c | d) = H(c) − H(c | d) H(c | d) = Σ (size_i / N) · H(child_i) (weighted)

Outlook wins, so it is the root. Overcast has entropy 0 (4 yes, 0 no): a pure leaf. Recurse on sunny and rainy.

Tree building and numeric attributes

  • Tree: inner nodes test one attribute, leaves hold a class. History: CLS 1966, ID3 1979, C4.5 1993.
  • Algorithm: if all records have one class, make a leaf. If no test gives positive gain, make a leaf with the majority class. Otherwise take the (attribute, threshold) with maximum IG, split, recurse.
  • Numeric attribute: try thresholds t, H(c | d:t) = H(c|d<t)·P(d<t) + H(c|d≥t)·P(d≥t), keep the t with max IG. Example: reduced Iris (100 flowers, entropy 1) split at petal width 1.75 leaves weighted entropy ≈ 0.31.
  • Correlations between attributes are not considered by IG. IG of an ID-like attribute (last digit of SSN) is about 0: useless.

Likely traps

Entropy is maximum when classes are equally frequent, not when one dominates, and it does not grow with the number of records. Entropy 0 means every record in the node has a known class, not that the node is useless.

09 · Decision trees: growing, overfitting, pruning

6 min

The Iris experiment

  • Iris split 50-50 (75 train, 75 test, random_state=10). Class entropy 1.58 (max is log2 3 = 1.585).
  • IG per attribute, best threshold: petal length (2.6) and petal width (0.75) 0.94, sepal length (5.75) 0.61, sepal width (3.25) 0.41. The root is a tie between the petal attributes; the slides use petal width ≤ 0.75, which isolates all setosa.
  • The weighted entropy of the children is always lower than the parent's, even if one child has higher entropy.
  • The training set was deliberately altered: two class labels changed, to show overfitting.

Overfitting and pruning

  • Hypothesis h overfits if another h' has higher training error but lower error on the whole data set. Causes: noise, and non-representative training data.
  • Training error is a lower limit of the new-data error. Test error is the realistic estimate.
  • Occam's razor: simpler is better, other things equal. Pruning simplifies the tree.
  • Hyperparameters (chosen by us, not learned): max_depth, min_samples_leaf, min_samples_split (what "X is small" means), max_leaf_nodes, ccp_alpha (post-pruning).
  • Choose them by cross-validation on the training set: not on training error (always prefers the deepest tree), not on the test set (no longer a fair estimate).

Impurity functions

Entropy = − Σ f_j log2 f_j criterion="entropy" Gini = 1 − Σ f_j² (sklearn default) max 1 − 1/C, min 0 Misclass = 1 − max_j f_j (optional in the slides) Gini split gain = GINI_parent − Σ (N_i / N) · GINI(child_i)

Weather, split on outlook: root Gini 1 − (9/14)² − (5/14)² = 0.459; after split (5/14)·0.48 + 0 + (5/14)·0.48 = 0.343; reduction 0.116. In practice the impurity measure has low impact; the pruning strategy has high impact.

Data leakage

  • Route 1, preparation on all data: filling the 303 missing NordicMart ages with the mean of all 3000 rows. Correct: split first, compute on training rows, apply the same number to test. Same for scaling, encodings, outlier thresholds, feature selection.
  • Route 2, features from the future (target leakage): days since last buy measured today, loyalty card cancelled, retention offer sent. Every feature must be known at prediction time.
  • Symptoms: results too good to be true, one attribute with enormous IG, a tree that is a single stump on it. Also the same individual in train and test: split by individual, not by row.

Properties

  • Non-parametric. Finding the best tree is NP-complete, so building is greedy (max immediate gain, no guarantee of the best tree).
  • Training cost O(D·N·log N). Classifying a record is O(h), h = tree height.
  • Robust to noise if pruned; redundant attributes are not a problem. scikit-learn trees do not take categorical attributes directly.

Likely traps (the slides' own closing questions)

  • Marital status near the root of an Adult-income tree: it predicts wealth, it is not shown to cause it. Attributes absent from the tree are not shown to be non-causes either.
  • Churn tree with "days since last buy > 90" at the root and near-maximum IG: check for target leakage first.

10a · Model selection and reliable estimates

5 min

Core ideas

  • Parameters are learned (tests and thresholds of tree nodes). Hyperparameters are set by us. Model selection = choose algorithm and hyperparameters.
  • Holdout should be stratified (same class proportions in both parts), essential with rare classes. Small data: 80/20 or 90/10. Large data: 70/30 is affordable.
  • Winner's curse: 20 random "models", 50 test records, keep the best test accuracy: about 63%, while the true accuracy of each is 50%. Selecting on the test score makes it optimistic.
  • Train / validation / test: tune on validation, retrain the best configuration on train + validation, score once on test. Fast, but the choice rests on one smaller portion (noisy) and uses less data for learning.
  • k-fold CV (k = 5 or 10, stratified by default for classification): every record is validated once and trains k−1 times. Gives mean and std (an error bar). Final model is learned on all training records.
  • Variants: repeated k-fold, leave-one-out (k = N, expensive, no randomness), group k-fold (all rows of one customer in the same fold).
  • Leakage inside CV: preparation steps (fill-in, scaling) must be recomputed inside each round on its training folds. That is what a Pipeline does.

Recipes and search

c = number of hyperparameter configurations. GridSearchCV tries every combination; RandomizedSearchCV a fixed budget. Example: max_depth {2,3,4,5,6} × min_samples_leaf {1,10,30} × criterion {gini, entropy} = 30 configurations, k = 5 → 150 + 1 trainings.

1-std rule: NordicMart CV accuracy for depth 2, 3, 4, 5 is 88.7, 88.8, 89.0, 88.6 (std 0.6 to 1.0). Differences are smaller than the std, so among configurations within one std of the best take the simplest: depth 2 or 3. A heuristic, not a statistical test.

How precise is a test error?

  • Each test record is a Bernoulli trial. With N test records and E errors, f = E/N. For N ≥ 30, f is roughly normal around the true error p, with sd √(p(1−p)/N).
  • z for the confidence level: 90% → 1.64, 95% → 1.96, 99% → 2.58. Rough interval: f ± z·√(f(1−f)/N). The slides use the Wilson score interval (more accurate, pessimistic).
  • Width shrinks as 1/√N: 4× the data, half the width.

Statistical pruning (C4.5)

Grow the full tree, then work bottom-up near the leaves using only training data. Compare e_l (weighted pessimistic error of the subtree's leaves) with e_r (pessimistic error if the root became a leaf). Prune if e_r ≤ e_l. Slide example (z = 0.67): e_l = 0.51 > e_r = 0.45, so the subtree is pruned.

Likely traps

Recipe 2 (tuning on test) is the one to recognise as wrong. CV is done on the training part; the test set is touched once at the end. Grid search cost is configurations × k, plus one final training.

Accuracy misleads with imbalanced classes. Precise alarms, but three churners out of four are missed. The baseline has precision undefined and recall 0. When error costs differ, look at precision and recall separately.

More than two classes

Per class: precision_i = TP_i / P_i (column total), recall_i = TP_i / T_i (row total). Slide example, 200 records, accuracy 140/200 = 0.70:

Taking chance into account

Cohen's κ = (Pr(o) − Pr(e)) / (1 − Pr(e)) = (correct − chance) / (N − chance) MCC = (TP·TN − FP·FN) / √((TP+FP)(TP+FN)(TN+FP)(TN+FN)) range [−1, 1]
  • Chance = a random classifier predicting classes in the same proportions as yours. 3-class example: 82 correct by chance, κ = (140−82)/(200−82) = 0.49 (accuracy 0.70).
  • κ: 1 perfect, 0 no better than chance, <0 worse. NordicMart tree: κ = 0.26, MCC = 0.28; baseline κ = 0.

Cost of errors and the threshold

  • NordicMart cost matrix: offer to a flagged customer €10; a churner not flagged costs €100 of margin (assumption: the offer keeps the churner).
  • Total cost: nobody gets the offer €10,800 · everybody gets it €7,920 · tree at threshold 0.5 €8,480 (28 FP, 82 FN) · tree at threshold 0.15: €6,460, better than both.
  • Cost-sensitive learning: resampling, or weights such as class_weight={0:1, 1:10} or "balanced"; or keep the model and move the threshold.
  • Soft classifier: output P(positive), class = P ≥ t. Lower t: more positives predicted, recall up, precision usually down. Multi-class: take the max probability.

Lift, ROC, AUC, precision-recall

  • Cumulative gains / lift: sort test records by decreasing P(positive); % of all positives found in the top x%. Lift = gains / x, the factor over random. Only the ranking matters.
  • ROC curve: x = FP rate = FP/T_neg (1 − specificity), y = TP rate = recall. One threshold = one point. Drawing it: sort by decreasing probability, start at (0,0), a positive is a step up, a negative is a step right, tie is a diagonal step, end at (1,1).
  • AUC = probability that a random positive scores higher than a random negative. 1 perfect, 0.5 random, insensitive to class proportions. NordicMart tree: 0.71. roc_auc_score, scoring="roc_auc".
  • NordicMart ROC points: t = 0.5 gives TP rate 0.24, FP rate 0.04; t = 0.15 gives 0.51 and 0.15.
  • Precision-recall curve: random level is the positive rate (12%). More informative than ROC when positives are rare. Summary: average precision (0.29).

Likely traps

"Best according to what?" is the lecture. 87.8% accuracy is below the 88.0% baseline yet the model has real signal (κ 0.26): accuracy alone is the wrong judge. Know which average exposes a rare class (macro) and which equals accuracy (micro).

11 · Naive Bayes, logistic regression, kNN

5 min

Naive Bayes

Pr(H | E) = Pr(E | H) · Pr(H) / Pr(E) prior → posterior Pr(c | E) ∝ Pr(E1 | c) · Pr(E2 | c) · … · Pr(ED | c) · Pr(c) (independent given the class)
  • Training = counting conditional frequencies. Pr(E) is the same for every class, removed by normalising.
  • Weather, new day (sunny, cool, high humidity, windy): likelihood yes 0.0053, no 0.0206, so Pr(yes) = 20.5%, Pr(no) = 79.5%.
  • Zero-frequency problem: one zero kills the whole product. Laplace smoothing: (count + α) / (class_count + α·V), α = 1 typically. Pr(overcast | no) = (0+1)/(5+3) = 0.125.
  • Missing values: omit the attribute from the product (record to classify) or do not count it (training record).
  • Gaussian NB for numeric attributes: per class and attribute, mean μ and std σ, use the normal density in place of the frequency.
  • Independence fails: a duplicated attribute (temperature in °F and in °C) counts the same evidence twice, so probabilities get too extreme (0.57 yes flips to 0.37).
  • sklearn: GaussianNB (var_smoothing), CategoricalNB (alpha), MultinomialNB / BernoulliNB (text), predict_proba.

Log loss

ℓ = −y·ln(p) − (1−y)·ln(1−p) = −ln of the probability given to the true class, averaged. Lower is better. 0.9 costs 0.11, 0.5 costs 0.69, 0.1 costs 2.30, and it tends to ∞ as p → 0. Reference: constant 12% for everyone gives 0.37 on NordicMart; a useful probabilistic model must beat it. AUC judges ranking only, precision and recall judge one threshold only, log loss judges whether "30%" really means 30%. log_loss, scoring="neg_log_loss".

Logistic regression

z = w·x + w0 Pr(y=1 | x) = σ(z) = 1 / (1 + e^−z) ln( p / (1−p) ) = w·x + w0
  • Log-odds are linear in the attributes, so the boundary is linear. z = 0 ↔ probability 0.5.
  • Weights learned by maximum likelihood = minimising log loss; the loss is convex (one minimum).
  • Weight w_j: log-odds change per +1 in x_j; the odds are multiplied by e^w_j. With standardised attributes, "+1" is one std, so sizes are comparable.
  • NordicMart weights: days since last buy +0.85 (odds ×2.35), web sessions −0.48 (×0.62), tickets +0.37 (×1.45), store-only +0.30 (×1.35).
  • Standardise with StandardScaler inside a Pipeline; μ and σ from training data only (leakage otherwise).
  • Hyperparameter C = penalty on large weights; small C = strong penalty. class_weight="balanced" for imbalance. Correlated attributes make single weights unstable.
  • Multi-class from binary: one-vs-rest = C problems (each imbalanced); one-vs-one = C(C−1)/2 problems, voting (3 classes: 3 and 3; 10 classes: 10 and 45). OneVsRestClassifier, OneVsOneClassifier; SVC uses OVO internally.

k-nearest neighbours

  • Lazy, instance-based: the training set is the model. Classify by majority vote of the k closest training records. Hyperparameters: k and the distance.
  • Distances: Euclidean (default), Manhattan, Minkowski (includes both), Mahalanobis; nominal attributes 0/1.
  • Always standardise: without scaling the attribute with the largest numbers decides (spend differs by 100 EUR vs tickets by 3).
  • k is a complexity hyperparameter: k = 1 gives a jagged, overfit boundary, huge k a smooth underfit one (NordicMart, k = 401, threshold 0.5: no alarm at all).
  • Costs O(N·D) per prediction (KD-tree and ball tree help), keeps all data in memory. Curse of dimensionality: distances become similar. No missing values allowed. Probability = fraction of the k votes.

Likely traps

Ranking quality (AUC) and probability quality (log loss) are different. Naive Bayes: independence assumption and why it still works for ranking. kNN: scale matters. Standardisation is learned on training data only, inside each CV round.
