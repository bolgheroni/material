LECTURE 08

Classification, validation and entropy

1. Supervised classification

The data set X has N individuals with D attribute values each. A class vector Y gives, for each individual, one of C class values assigned by experts (the supervisors); the soybean data set labels plants with diseases. The goal is to guess y(x) for individuals the experts have not examined, by learning a classification model.

A model is a parametrized algorithm. Developing one has three steps: choose the learning algorithm, let it learn its parameters, assess its quality. At run time the algorithm uses the learned parameters.

M(x, θ) = y_pred(x) learning: find θ that reduces the prediction error as much as possible
Reading the symbols
  • x: one record, i.e. the list of its attribute values (for a customer: age, spend, tickets, …).
  • θ (theta): the model’s parameters, the numbers the algorithm learns from the data. For a line they are its coefficients; for a tree they are the tests and thresholds.
  • M(x, θ): the model, a function that reads a record and the parameters and returns a class. y_pred is that returned class.
  • In words: learning means adjusting θ until the predicted classes agree with the experts’ labels as often as possible.

Worked example · a line as a classifier

Two attributes, two classes. Decision function: θ₁d₁ + θ₂d₂ + θ₃ ≥ 0 ⇒ class c₁, otherwise c₂. Even with the best θ a straight line makes errors on some data. A quadratic θ₁d₁² + θ₂d₂² + θ₃d₁d₂ + θ₄d₁ + θ₅d₂ + θ₆ has more shattering power: it can carve the plane into more homogeneous regions. “All models are wrong, but some are useful” (George Box).

VC dimension measures shattering power. N points admit 2N labellings; if a model can realize all of them, its VC dimension is at least N. A straight line in the plane has VC dimension 3 (any 3 non-collinear points can be separated in all 8 ways, 4 points cannot always). In real data even a line is often not bad.

Two flavours: crisp classifiers output one label; probabilistic (soft) classifiers output one probability per class. Lecture 10b exploits the second kind.

2. Measuring a classifier

Training error counts mistakes on the data used for learning. Generalization error counts mistakes on new data: this is the one we care about, and it is unknown because new data have no labels yet. Training error is optimistic: a lookup table that memorizes the data scores 0%. More flexibility always lowers the training error, so it cannot choose the model.

The train/test split

  • Split the labelled data at random: training set to learn, test set (labels hidden from the model) to estimate. Proportions are the experimenter's choice: 80-20, 67-33, 50-50.
  • Assumption: both parts look like the future data, so the sample must come from a random process.
  • Workflow: (1) learn on training; (2) predict the test set and compare with the true labels; (3) use the model on new individuals, and when true labels arrive, compare them with the estimate.
  • The test set is the future: never learn from it, never choose by looking at it, otherwise its error is no longer an honest estimate. The same holds for anything computed from the data before the split (data leakage, lecture 09).

The baseline: how good is good?

The majority-class rule always predicts the most frequent class, with no learning at all. NordicMart has 12% churners, so “nobody churns” is right 88% of the time. Iris has three balanced classes, so the baseline is 33%. A model is interesting only if it beats the baseline.

Cross-validation, the idea

A different random split gives a different test error, and with small data sets the variation can be large. Cross-validation uses every individual for both training and testing, fairly: split into k = 5 folds; in each of 5 rounds one fold is the test set and the other four train the model; report the mean and the standard deviation of the 5 errors.

“Accuracy 88%” means nothing until you know the baseline. With 12% positives a classifier that always says “no” has 88%.

3. Decision trees: using one

Decision trees are a good compromise: decent performance, fast to train and to run, easy to understand. History: CLS (Hunt et al., 1966), ID3 (Quinlan, 1979), C4.5 (Quinlan, 1993). A tree is a tree-shaped set of tests: inner nodes test one attribute, leaves hold a class.

execute(node, x): if node is inner: if test on attribute d of x holds: execute(node_yes, x) else: execute(node_no, x) else: predict the class c of the leaf
In words
  • Start at the root. At an inner node, check the test on the record x (for example “humidity > 75?”) and follow the “yes” or the “no” branch. Repeat until you reach a leaf, then output the class stored in the leaf.
  • execute calls itself on the child node: that is a recursion, the natural way to walk a tree.

4. Entropy: information as surprise

How interesting is a pattern? Information theory (Claude Shannon, 1948) answers with entropy: the information content of a source, its surprise. Two weather stations send one symbol per day: A always sends “sunny”; B sends sunny, cloudy, rainy or snowy equally often. B carries more information because you cannot predict tomorrow's symbol before receiving it.

Worked example · fewer bits for likely symbols

Four symbols with equal probability 0.25 need 2 bits each (A=00, B=01, C=10, D=11). With probabilities 0.5, 0.25, 0.125, 0.125 the code A=0, B=10, C=110, D=111 averages 0.5·1 + 0.25·2 + 0.125·3 + 0.125·3 = 1.75 bits. Three equally likely symbols: the simple code A=0, B=10, C=11 averages 1.67 bits, and coding several symbols together gets below 1.6, towards log23 = 1.585. The best average code length is the entropy:

H(X) = − Σ_j p_j · log2(p_j)
Reading the symbols
  • pj: the probability of symbol j (for the weather: the fraction of days of each class).
  • Σj (sigma): add up the term for every symbol j.
  • log2(p): the power to which 2 is raised to get p. It is always ≤ 0 for p ≤ 1 (log2 0.5 = −1), so the minus sign makes each term positive. A rare symbol (small p) has a large −log2 p: it is surprising.
  • So H is the average surprise in bits: 0 when one symbol is certain, 1 bit for a fair coin, log2V at most for V symbols.
  • High entropy: similar probabilities, a flat histogram, hard to guess. Low entropy: some values much likelier, a peaked histogram.
  • Classification link: low entropy of the class labels means low diversity, high purity, a clear majority. We look for logical tests that split the data into purer subsets.

Worked example · entropy of the weather class

The weather (play tennis) data: 14 days, 4 categorical attributes (outlook, temperature, humidity, windy), class play: 9 yes, 5 no.

p_yes = 9/14 = 0.643 log2 = −0.637 p_no = 5/14 = 0.357 log2 = −1.485 H = −(0.643·(−0.637) + 0.357·(−1.485)) = 0.410 + 0.530 = 0.940 bits

Close to 1: the class is hard to guess. By-hand cheat sheet: −p·log2p is 0.500 for p = 1/2, 0.528 for 1/3, 0.390 for 2/3, 0.311 for 3/4, 0.464 for 1/5, 0.529 for 2/5, 0.442 for 3/5, 0.258 for 4/5. So H(2/5, 3/5) = 0.971 and H(1/4, 3/4) = 0.311 + 0.500 = 0.811; H(1, 0) = 0.

5. Information gain

The information gain of a test is the reduction of the class entropy it achieves: what we gain in predicting the class by knowing the outcome of the test. After a split, the new entropy is the weighted sum of the entropies of the parts, with weights equal to the relative sizes.

IG(c | d) = H(c) − H(c | d) H(c | d) = Σ_i (N_i / N) · H(c | outcome_i)
Reading the symbols
  • c: the class; d: the attribute whose test we are evaluating.
  • H(c): class entropy before the split. H(c | d): class entropy after it, “given that we know the outcome of the test on d”.
  • outcomei: the i-th branch of the test (sunny, overcast, rainy). Ni: records in that branch, N: records in the node. Ni/N is the weight of the branch.
  • In words: IG = entropy before − weighted average entropy of the children. A big IG means the children are much purer than the parent.

Numeric attributes

Split by a threshold t: d < t versus d ≥ t. Try the thresholds, compute the weighted entropy of the two parts and keep the one with the maximum gain.

IG(c | d:t) = H(c) − [ H(c | d<t)·P(d<t) + H(c | d≥t)·P(d≥t) ] IG(c | d) = max_t IG(c | d:t)
Reading the symbols
  • t: a threshold on the numeric attribute d. It cuts the records into two parts: d < t and d ≥ t.
  • P(d < t): the fraction of records in the low part (the weight of that part). H(c | d<t): class entropy inside it.
  • maxt: try every candidate threshold and keep the one with the largest gain; that value is the gain of the attribute d.

Worked example · reduced Iris, petal width, threshold 1.75

100 flowers, classes 1 and 2 (50 each): H(class) = 1. Threshold 1.75 gives a low part of 54 records (49 class 1, 5 class 2) and a high part of 46 (1 class 1, 45 class 2).

H(low) = −(49/54·log2 49/54 + 5/54·log2 5/54) = 0.445 H(high) = −(1/46·log2 1/46 + 45/46·log2 45/46) = 0.151 H(class | d:1.75) = 0.54·0.445 + 0.46·0.151 = 0.31 IG = 1 − 0.31 = 0.69

What IG can and cannot tell you. Predicting long life, IG(LongLife | HairColor) = 0.01, IG(Smoker) = 0.2, IG(Gender) = 0.25, IG(LastDigitSSN) = 0.00001: the gain ranks useful attributes above useless ones. Correlations between attributes are not considered.

Answer to “which attribute should we test?”

The attribute (and threshold) with the maximum information gain on the current set X. Partition X by the outcomes of the test and recurse on each part.

Exam traps

  • Entropy is maximum with equally frequent classes, not when one class dominates; it does not depend on the number of records.
  • A node with entropy 0 is a pure node (known class), not a useless one.
  • The weighted entropy of the children is never above the parent's, so IG ≥ 0.

Worked example · the weighted entropy always drops

Take the node with entropy 0.622 and 34.7% of the data (26 records). Its children have entropy 0 (22.7%) and 1.224 (12%). One child has higher entropy than the parent, yet the weighted sum is lower: (0·22.7 + 1.224·12)/34.7 = 0.42 < 0.622.

When does the recursion end? Most leaves are pure, so recursion is impossible. One leaf is not pure but no test gives a positive gain; its label is the majority class (or one of the tied classes). Training set error: 1.33%, one of 75 training examples misclassified (one of the two records in the rightmost leaf).

buildTree(X, p): if all class values of X are c: return leaf p with label c if no attribute gives positive IG in X: return leaf p with the most frequent class of X find (d, t) with maximum IG in X create p_left, p_right buildTree(X[d < t], p_left); buildTree(X[d ≥ t], p_right)
In words
  • X: the training records that reach this node; p: the node being built. Line by line: (1) if all records have the same class, make a leaf with that class; (2) if no test helps (no positive IG), make a leaf with the most frequent class; (3) otherwise choose the best attribute and threshold (d, t), split X in two parts and apply the same procedure to each part.
  • It is greedy: at each node it takes the best split now, without looking ahead.

2. Errors and overfitting

Training set error: run the tree on the training set itself (class hidden) and count discordances. It can be above zero because of the limits of decision trees (single-attribute tests can fail) or insufficient information in the predicting attributes (identical attributes, different classes). The 1.33% is probably a lower limit of the error on new data; we want an upper limit, or at least a realistic value: the test set error.

Two wrong labels out of 75 double the test error: a fully grown tree trusts every training example.

Overfitting, formally

A tree is a hypothesis h about the relation between predicting attributes and class. h overfits the training set if there is an alternative h′ with errortrain(h) < errortrain(h′) and errorX(h) > errorX(h′), where errorX is the error on the entire data set. When the learning is affected by noise, test performance is much worse than training performance.

  • Causes: (1) noise: bad values or labels, unusual cases; (2) lack of representative instances: some situations under-represented or absent in training.
  • Occam's razor: other things being equal, simple theories are preferable; a long hypothesis that fits the data is more likely a coincidence. Pruning simplifies a tree, and we need quantitative guidelines for it.

4. Impurity functions

To choose the attribute that splits the data, look for the split with maximum purity of the children. Three measures of the impurity of a node with class frequencies fj:

Entropy = − Σ f_j log2 f_j (criterion="entropy") Gini = 1 − Σ f_j² = Σ f_j (1 − f_j) (sklearn default; max 1 − 1/C, min 0) Misclass. = 1 − max_j f_j (optional) Gini gain = GINI_parent − Σ_i (N_i / N) · GINI(child_i)
Reading the symbols
  • fj: the fraction of the node’s records that belong to class j (the class frequencies, adding up to 1). C: number of classes.
  • Σj: sum over the classes. Entropy and Gini are both 0 for a pure node and largest when the classes are equally mixed.
  • Misclassification is the error you would make by labelling the node with its majority class. Gini gain works like information gain: parent impurity minus the weighted impurity of the children (Ni/N = share of records in child i).

Gini intuition: assign a class at random following the node's class frequencies; fj(1 − fj) is the probability of a wrong assignment for class j, and the sum is the total probability of a wrong classification. Used by CART, SLIQ, SPRINT.

Worked example · Gini on the weather data, split on outlook

root (9 yes, 5 no): 1 − (9/14)² − (5/14)² = 0.459 sunny (2/3): 1 − 0.4² − 0.6² = 0.48 overcast (4/0): 0 rainy (3/2): 0.48 after the split: 5/14·0.48 + 4/14·0 + 5/14·0.48 = 0.343 reduction: 0.459 − 0.343 = 0.116

Misclassification error is linear in the class frequency, so an error in the frequency passes entirely into the impurity; entropy and Gini have a varying derivative and a minimum around the centre, so they are more robust to errors in the frequency when the classes are balanced. In practice the impurity measure has low impact on the result; the pruning strategy has high impact.

5. Data leakage

Information that will not be available at prediction time reaches the model during learning. Effect: the evaluation is too optimistic, a great test score and poor results in production. Two routes:

Route 1 · preparation on all the data

NordicMart has 303 missing ages. Leak: fill them with the mean age of all 3000 rows, then split. Correct: split first, take the mean age of the training rows, apply that same number to the test rows. Same for scaling, encodings, outlier thresholds and feature selection.

Route 2 · features from the future

NordicMart churn = no purchase in the 90 days after the snapshot. Leaking features: days since last buy (measured today, not at the snapshot), loyalty card cancelled, retention offer sent (only to customers already flagged). Rule: every feature must be known at prediction time.

  • Symptoms seen with a tree: results too good to be true, one attribute with an enormous information gain, a tree that is a single stump on that attribute.
  • Also the same individual in training and test (duplicates, several rows per customer): split by individual, not by row.
  • Remedy: split first, prepare on training only, check every feature's timing.

6. Properties of decision-tree induction

  • Cost: height O(log N); each level touches all data, each node all attributes: O(D·N·log N). Binary numeric splits O(N log N) and pruning O(N log N) add nothing to the order. Classifying a new record: O(h), extremely efficient.
  • Non-parametric: no assumption on the distributions of classes and attributes.
  • Finding the best tree is NP-complete: the algorithm is greedy (the best immediate gain at each decision point, part of the hill-climbing family, no guarantee of the best result; a sequence of individually sub-optimal choices could give a better final tree).
  • Robust to noise in the labels if pruned; redundant attributes cause no difficulty; deep nodes are often irrelevant (few training records) and pruned.
  • scikit-learn trees do not accept categorical attributes directly: transform them first.

Think-questions from the lecture, with answers

  • Why greedy instead of trying all trees? The number of trees is astronomically large and finding the optimal one is NP-complete; the greedy choice is cheap and good in practice.
  • Marital status near the top of a wealth tree on the Adult data: a major cause of wealth? No. The tree shows that it predicts the class, not that it causes it.
  • Attributes not in the tree: not causes? No. A correlated attribute may simply have been redundant once another was chosen.
  • A churn tree has “days since last buy > 90” at the root with near-maximum IG: first check? Target leakage: the feature is measured today while churn is defined on the following 90 days.

LECTURE 10a

Model selection and reliable estimates

1. Why evaluate

Questions to answer: which kind of model is best for this problem? Which learning algorithm? Which hyperparameter values? Evaluation estimates the run-time performance (the model in use on new data, hence the expected cost of errors) and compares alternatives, independently of the algorithm that built the model. Every estimate has a random component: another sample, another number.

Worked example · oil-slick detection

Dark regions in radar satellite images can be oil spills or look-alikes caused by wind and sea conditions; manual inspection is expensive and slow. Spills are rare, so classes are imbalanced. The deployed system pre-selects images for manual check, so there is a trade-off: missed spills versus false alarms. Evaluation guides that trade-off.

Parameters are learned from data (tests and thresholds of the tree nodes); hyperparameters are chosen by us (max_depth, min_samples_leaf, criterion). Model selection = choose the learning algorithm and its hyperparameters through several train/evaluate loops: a trade-off between the quality of the search and the computing time.

2. Holdout, validation and test

  • Holdout: one random split of the supervised data X. Stratification (same class proportions in both parts) is essential with rare classes. The test error estimates the run-time error.
  • How much data for testing? Small data set: 80/20 or 90/10; large: 70/30 is affordable. Flexible models need many training examples, simple models learn from little. Critical domains (medicine, driving) need reliable estimates. A larger test set gives a more stable estimate. Rare classes: enough of them in the test set (NordicMart: 108 churners among 900 test customers). Evaluation is cheap, training is not.

Worked example · the winner's curse

Take 20 “models” that answer at random (coin flips), a test set of 50 records with two balanced classes, and keep the model with the best test accuracy. The expected accuracy of the winner is about 63%, while the true accuracy of every model is 50% (computed exactly: E[max of 20 Binomial(50, 0.5)]/50 = 0.631). Selecting by the test score makes the test score optimistic.

Train, validation, test

  1. For each configuration, learn on the training set and score on the validation set.
  2. Learn the best configuration again on training + validation.
  3. Score once on the test set.

Pros

  • Fast: one training per configuration.
  • Hyperparameters chosen on data independent of the final test, so more reliable than plain holdout.

Cons

  • The choice rests on one smaller portion (the validation set): noisy, less reliable than cross-validation.
  • The three-way split leaves less data for learning.

3. Cross-validation

Partition the training data at random into k folds (stratified if needed). k rounds: one fold for validation, k − 1 for training. Combine the k scores into a mean and a standard deviation. Every record is in training k − 1 times and in validation once. Typical values: k = 5 or 10. The final model is learned on all the training records.

  • Variants: stratified k-fold (class proportions in each fold; scikit-learn default for classification); repeated k-fold (several random partitions, averaged); leave-one-out (k = N: no randomness, very expensive, intrinsically non-stratified); group k-fold (all records of one individual in the same fold: several rows per customer, patient or machine).
  • Leakage inside CV: each validation fold is a small future. Preparation steps (fill-in values, scaling) computed once on all the training data and then cross-validated are wrong; recompute them inside each round on its training folds. It is the lecture-09 rule applied k times.
  • Cons and pros: the train/validate loop is repeated k times; but the score is averaged (more reliable, with an error bar), and the final model uses every example.

The whole process: for several kinds of model, search hyperparameters (CV on the training part), estimate on the test set, and send the overall best to run time.

5. How precise is a test error?

6. Statistical pruning (the C4.5 strategy)

Grow the full tree, then work bottom-up. For a subtree near the leaves, let el be the weighted pessimistic error of its leaves and er the pessimistic error of its root turned into a leaf. Prune if er ≤ el. It uses only the training data; the pessimistic error is the upper limit of a confidence interval on f.

Worked example (z = 0.67, after Witten et al.)

A node with N = 14, f = 5/14 has er = 0.45 as a leaf. Its three leaves: N = 6, f = 2/6, e = 0.47; N = 2, f = 1/2, e = 0.72; N = 6, f = 2/6, e = 0.47.

e_l = (6·0.47 + 2·0.72 + 6·0.47) / 14 = 0.51 > e_r = 0.45 ⇒ prune

  • CV is run on the training part; the test set is touched once at the end.
  • Grid-search cost = configurations × k, plus one final training.
  • Overlapping error intervals are not evidence that one model is better.

4. Taking chance into account

The problem. Accuracy ignores how easy the task is. If 2% of patients have a disease, “no disease” for everybody scores 98%. At NordicMart 12% of customers churn, so “nobody churns” scores 88%, while our tree scores 87.8%. The tree looks worse, yet it actually finds some churners. We need a measure of the improvement over guessing.

The baseline. A random classifier says “churn” as often as our model does, but independently of the truth. Its accuracy is the “correct by chance” level. Two measures build on this idea: κ and MCC.

Cohen's κ: how much of the possible gain over chance did we get?

κ = (correct − correct by chance) / (perfect − correct by chance) = (Pr(o) − Pr(e)) / (1 − Pr(e))
Reading the symbols
  • Pr(o): the observed agreement = the accuracy (fraction of correct predictions). Pr(e): the agreement expected by chance (fraction a random classifier with the same predicted proportions would get right).
  • Numerator: how much better than chance we are. Denominator: how much better than chance it was possible to be. So κ is “the fraction of the possible improvement we achieved”.

Worked example · NordicMart tree (TP 26, FN 82, FP 28, TN 764, N = 900)

  1. Marginals. Real churners 26 + 82 = 108, real non-churners 792. The model says “churn” 26 + 28 = 54 times and “stay” 846 times.
  2. Correct by chance. Churners: 108 × 54 / 900 = 6.5. Non-churners: 792 × 846 / 900 = 744.5. Total = 751.
  3. Actual correct. 26 + 764 = 790. Perfect would be 900.
  4. κ = (790 − 751) / (900 − 751) = 39 / 149 = 0.26. The tree beats chance by 39 customers out of the 149 it could have gained: a weak but real signal.

The baseline “nobody churns” says “churn” 0 times, so chance already predicts 792 correct and it gets exactly 792. Gain 0, so κ = 0, even with 88% accuracy.

Worked example · three classes (a, b, c)

The classifier predicts a, b, c in the proportion 100 : 60 : 40 = 50% : 30% : 20%. Splitting every row of the true classes (120, 60, 20) in that proportion gives, on the diagonal, 120·0.5 + 60·0.3 + 20·0.2 = 60 + 18 + 4 = 82 correct by chance. Our classifier gets 140; the perfect one 200.

gain: 140 − 82 = 58 possible: 200 − 82 = 118 κ = 58 / 118 = 0.49 (accuracy 0.70)
  • Scale: 1 perfect agreement, 0 no better than chance, < 0 worse than chance (−1 only in special binary cases, a perfect swap).
  • Pr(o) = Σ TP_i / N (the accuracy) and Pr(e) = Σ T_i·P_i / N², where T_i and P_i are the true and predicted counts of class i.
  • Binary shortcut: κ = 2(TP·TN − FP·FN) / [ (TP+FP)(FP+TN) + (TP+FN)(FN+TN) ].

MCC: the correlation between prediction and truth

MCC = (TP·TN − FP·FN) / √((TP+FP)(TP+FN)(TN+FP)(TN+FN)) range [−1, 1]
Reading the symbols
  • TP, TN, FP, FN: the four cells of the confusion matrix (true positives, true negatives, false positives, false negatives).
  • Numerator TP·TN − FP·FN: large when the correct cells are big and the error cells are small. Denominator: product of the four row and column totals, under a square root, which rescales the result to between −1 and 1.
  • (TP+FP) = predicted positives, (TP+FN) = real positives, (TN+FP) = real negatives, (TN+FN) = predicted negatives.

The numerator is large when the model is right on both classes and small when it makes many errors; the denominator rescales to −1..1. For NordicMart: numerator = 26·764 − 28·82 = 19,864 − 2,296 = 17,568; denominator = √(54 · 108 · 792 · 846) = 62,511; MCC = 0.28. It uses all four cells of the matrix, is 0 for the “nobody churns” baseline, and stays reliable with imbalance.

What to remember

  • With imbalanced classes never judge by accuracy alone: add κ or MCC, or precision, recall and F1.
  • κ asks “how much better than guessing?”; MCC asks “how correlated are prediction and truth?”. Both are 0 at chance and 1 at perfect.
  • For the exam, know the κ idea (observed vs expected by chance) and be able to compute it from a matrix. In the lab: cohen_kappa_score, matthews_corrcoef.

6. Probabilistic classifiers: thresholds, lift, ROC, AUC

A crisp prediction is a label; a soft prediction is one probability per class. Choose crisp for an immediate automatic decision, soft when the prediction is part of a process with further steps (ranking, budget, human check). Crisp outputs often hide probabilities: a tree leaf holds the class fractions of its training records (the rightmost Iris leaf, 26 flowers split 1/2/23, gives P = (0.04, 0.08, 0.88)); small leaves give unreliable probabilities.

From probabilities to crisp: for binary problems put a threshold t on Pr(positive) (default 0.5, any value is legitimate); multi-class: the class with the maximum probability. Lowering t predicts more positives: recall rises, precision usually falls. For NordicMart the cost is minimized near t = 0.15 (€6,460, below both trivial strategies).

Same table, different axes: x = FP rate (fraction of stayers wrongly flagged, the false alarms) and y = TP rate (fraction of churners caught = recall).   • start at (0, 0): threshold above every score, nobody flagged;
  • next customer in the sorted list is a churner → the TP rate grows → step up by 1/#positives (here 1/4);
  • next customer is a stayer → the FP rate grows → step right by 1/#negatives (here 1/6);

For our table the path is: up, up, right, up, right, right, up, right, right, right, i.e. (0,0) → (0,.25) → (0,.5) → (.17,.5) → (.17,.75) → (.33,.75) → (.5,.75) → (.5,1) → (1,1).

A useless model mixes churners and stayers randomly, so the path wanders along the diagonal. Each point is a trade-off you can choose: for example, the point (0.17, 0.75) means “flag the top 4; you catch 75% of churners at the price of 17% of stayers flagged”. Choosing the threshold = choosing the point; the costs of the two error types (section 5) tell you which.

Naïve Bayes, logistic regression, k-nearest neighbours

Three more kinds of classifier with the same data and the same toolbox (NordicMart churn): probabilistic (Naïve Bayes), linear (logistic regression), instance-based (kNN).

1. Naïve Bayes

The question, and why we flip it

For a new record with attribute values E (say: store-only customer, 3 tickets, 14 months of tenure) we want, for each class c, the probability Pr(c | E): “given that I see these values, how likely is this record to belong to class c?” Then we predict the class with the highest probability. Read the bar “|” as “given that”.

Problem: we cannot count that directly. What we can count in the training data is the opposite direction: Pr(E | c), “among the customers of class c, how often do these values appear?”. Bayes' theorem converts one into the other:

Pr(c | E) = Pr(E | c) · Pr(c) / Pr(E) posterior = likelihood · prior / evidence
  • Prior Pr(c): how common the class is before looking at the record (12% of customers churn).
  • Likelihood Pr(E | c): how typical these values are inside the class. Counted in the training data.
  • Evidence Pr(E): how common these values are overall. Same for every class, so it will disappear (see below).
  • Posterior Pr(c | E): the updated belief after seeing the record. This is the answer. General form: Pr(H | E) = Pr(E | H) · Pr(H) / Pr(E), hypothesis H, evidence E.

Worked example · one attribute, as pure counting (NordicMart)

Imagine 1,000 customers. Prior: 12% churn, so 120 churners and 880 stayers. From the data: 35% of churners are store-only, and 16% of stayers are store-only.

  1. Store-only churners: 0.35 × 120 = 42 (this is Pr(E | churn) · Pr(churn), the numerator of Bayes).
  2. Store-only stayers: 0.16 × 880 ≈ 141.
  3. All store-only customers: 42 + 141 = 183 (this is Pr(E), the denominator: 0.18).
  4. Among the 183 store-only customers, the churners are 42/183 = 23%.
Pr(churn | store-only) = 0.35 · 0.12 / 0.18 = 0.23 prior 12% → posterior 23%

So Bayes' theorem is nothing but this: restrict to the customers who show the evidence, and see which fraction belongs to the class. It matches the direct count from the exploratory analysis (churn 23% for store-only customers, 10% for the others).

Many attributes: the “naïve” assumption

A record has D attributes, E = (E1, …, ED). We would need Pr(E1, …, ED | c): how often does this exact combination appear inside class c? With a handful of attributes the combination almost never occurs in the training data (the weather table has 14 rows, and the new day below never appeared), so the count is 0 or meaningless.

The trick: assume the attributes are independent of each other, once the class is known. Then the probability of the combination is the product of the single ones:

Pr(E | c) = Pr(E1 | c) · Pr(E2 | c) · … · Pr(ED | c) Pr(c | E) = Pr(E1 | c) · Pr(E2 | c) · … · Pr(ED | c) · Pr(c) / Pr(E)

Each factor is a simple frequency inside the class: “among the churners, what fraction is store-only?”, “among the churners, what fraction has 3+ tickets?”, and so on. Training is just counting, once per attribute and class. It is called naïve because the assumption is very strong and rarely true (store-only and few web sessions go together), yet the method works well in practice, especially for ranking.

The zero-frequency problem and Laplace smoothing

New day: overcast, hot, high, windy. Overcast never occurs with “no”: Pr(overcast | no) = 0/5, so the likelihood of no is 0 whatever the other attributes say, and Pr(yes) = 100%. One zero should not veto all the other evidence.

Pr(d = v_i | c) ≈ ( af(d=v_i, c) + α ) / ( af(c) + α·V )
Reading the symbols
  • d: an attribute (outlook). vi: one of its values (sunny, overcast, rainy). c: a class (yes or no).
  • af(d=vi, c): absolute frequency, the number of training records of class c where d has the value vi. For overcast and no it is 0.
  • af(c): how many training records belong to class c (5 days of “no”).
  • α (alpha): the smoothing amount, the “pretend count” added to every value. α = 1 is the standard choice (Laplace); α = 0 means no smoothing.
  • V: the number of different values of d (outlook has 3). We add α once for each of the V values, so the denominator grows by α·V and the probabilities still add up to 1.

Missing values, numeric attributes, and a failure case

  • Missing values: no need to discard the record. To classify, omit the attribute from the product (all likelihoods grow, the normalization compensates). In training, do not count the record for that attribute: frequencies are computed over the values present.
  • Gaussian Naïve Bayes for numeric attributes: within each class a normal distribution; from the training data take mean μ and standard deviation σ per attribute and class; use the density f(x) = (1/(σ√2π)) e−(x−μ)²/(2σ²) in place of the frequency. Example: f(temperature = 66 | yes) with μ = 73, σ = 6.2 is 0.0340; for sunny, 66, humidity 90, windy: likelihood yes 0.000036, no 0.000136, so Pr(yes) = 20.8%.
  • When independence fails: duplicate an attribute (temperature in °F and in °C: no new information, a linear transformation). Its evidence is counted twice and 85°F is more typical of “no” days, so that factor enters squared: Pr(yes) goes from 0.57 (yes) to 0.37 (no). Correlated attributes: the same effect, milder.

Measuring probabilities: log loss

AUC sees only the ranking; precision and recall see only the decisions at one threshold. Neither says whether a predicted 30% really means 30%. Log loss (cross-entropy) looks at the probability given to the class that actually occurred:

ℓ = − y·ln(p) − (1 − y)·ln(1 − p) = − ln(probability given to the true class) log loss = average of ℓ, lower is better 0.9 → 0.11 0.5 → 0.69 0.1 → 2.30 → ∞ as p → 0 (rewards confidence when right, punishes it heavily when wrong) reference: constant 12% for every customer → 0.37 on the NordicMart test set (a useful probabilistic model must stay below it)
Reading the symbols
  • y: the true label of the record, 1 if it is positive (churned) and 0 otherwise. p: the probability the model gave to “positive”. ln: the natural logarithm.
  • Only one of the two terms survives: if y = 1 the loss is −ln(p); if y = 0 it is −ln(1 − p). In both cases it is −ln of the probability given to what really happened.
  • Giving 0.9 to a true churner costs 0.11; giving 0.1 costs 2.30. Averaging ℓ over all records gives the log loss.

2. Logistic regression

The idea in three steps

  1. Score. Give every attribute a weight and add everything up: z = w0 + w1x1 + … + wDxD. A positive weight pushes towards the class “churn”, a negative one pushes away from it. This is the same weighted sum as in linear regression.
  2. Squash. z can be any number from −∞ to +∞, but a probability must lie between 0 and 1. The sigmoid σ(z) = 1 / (1 + e−z) bends z into (0, 1): z = 0 gives 0.5, large positive z gives almost 1, large negative z gives almost 0.
  3. Decide. p = Pr(churn | x) is the output. Predict churn when p is above a threshold (0.5 by default, any value is legitimate).

Because the sigmoid is monotonic, the boundary p = 0.5 is exactly the place where z = 0, a straight line (a plane with more attributes). That is why logistic regression is a linear classifier.

Pr(y = 1 | x) = σ(z) = 1 / (1 + e^(−z)) z = 0 → 0.5; z → +∞ → 1; z → −∞ → 0; monotonic odds = p / (1 − p) log-odds (logit) = ln( p / (1 − p) ) = w0 + w1·x1 + … + wD·xD ← linear in the attributes
Reading the symbols
  • σ (sigma): the sigmoid function. e ≈ 2.718. z: the score, the weighted sum of the attributes.
  • p: the probability of the positive class. odds = p/(1−p): how many times more likely positive than negative (p = 0.8 → 4 to 1). ln of the odds is the log-odds or logit.
  • w0: the intercept; w1…wD: one weight per attribute; x1…xD: the record’s attribute values. The key line says: the log-odds are exactly the weighted sum z.
  • monotonic: a bigger z always gives a bigger p, so ranking by z or by p is the same.

Worked example · odds and log-odds

p = 0.8: odds = 4 (“four to one”), log-odds ln 4 = 1.39. p = 0.5: odds 1, log-odds 0. p = 0.2: odds 0.25, log-odds −1.39. A linear boundary: for NordicMart with days since last buy and web sessions, the line P = 0.5 (and the line P = 0.15) separates the plane.

Why odds? Reading the weights

The odds say “how many times more likely is churn than stay”: p = 0.8 means 4 to 1. The surprising fact: z is not the probability and not the odds, z is the log-odds, ln(p / (1 − p)). So every weight acts on the odds by multiplication: if xj grows by 1, the log-odds grow by wj, hence the odds are multiplied by ewj. That is where “odds × 2.35 per standard deviation” in the table below comes from (e0.85 = 2.35).

Worked example · from a customer to a probability

Goal: turn one customer into a churn probability, using the weights of the table further below (illustrative numbers). Three steps.

Step 1 · describe the customer in z-scores. The attributes were standardized: value = (raw − average) / std, so 0 means “exactly average”, +1 means “one standard deviation above average”, −1 “one below”. Our customer:

  • days since last buy: 52 days more than average, and 52 days is one std → +1;
  • web sessions per month: 2.1 fewer than average, and 2.1 is one std → −1;
  • support tickets: exactly average → 0.

Step 2 · start from the intercept. The intercept w0 is the score of a customer with all z-scores 0, i.e. an average customer. It makes the model reproduce the base rate: with w0 = −2.0 the sigmoid gives 1 / (1 + e2) = 0.119 ≈ the 12% of customers who churn. So knowing nothing special about a customer, the model says 12%.

Step 3 · add each attribute’s contribution (weight × z-score), then squash with the sigmoid:

  • Learning: the weights minimize the average log loss on the training data (confident wrong predictions cost most). Equivalent to maximum likelihood: L(w) = Π piyi(1 − pi)1−yi, and −ln L is the sum of the log losses. Smooth and convex in w: a single minimum, solved numerically by the library.
  • Interpreting a weight: wj is the change of the log-odds when xj grows by 1, all other attributes fixed; equivalently the odds are multiplied by ewj. Its sign gives the direction of the effect. With standardized attributes, “grows by 1” is one standard deviation, so sizes are comparable across attributes. The intercept w0 is the log-odds of the average customer (all z-scores 0). Correlated attributes share the weight: single values are unstable, read them with care.

Worked example · what “learning the weights” means

Three training customers: A churned, B stayed, C churned. Try two sets of weights and look at the probability each gives to what really happened.

For a stayer, the probability given to the truth is 1 − p. Better weights make the data we actually observed more probable: the product is larger. Maximizing this product (maximum likelihood) is the same as minimizing the average −ln, the log loss. The library searches the weights numerically; the surface is convex, so there is one minimum and no local traps.

Extra! Why is it convex?

“Convex” means bowl-shaped: the straight segment between any two points of the surface never goes below the surface, so rolling downhill always ends at the same single bottom. Three facts give this:

  1. One record. Its loss as a function of its own score z is −ln σ(z) for a churner and −ln(1 − σ(z)) for a stayer. Both curves bend upward everywhere: the curvature is σ(z)·(1 − σ(z)), which is always positive (largest, 0.25, at z = 0). Example: for a churner the loss falls steeply when z goes from −2 to 0, less from 0 to 2, and never turns back up.
  2. Through the weights. The score z = w0 + w1x1 + … is a straight function of the weights, and a convex function of a straight function stays convex.
  3. Over all records. The average of convex functions is convex.

So the log loss is a single bowl in the weights. Two remarks: (a) a neural network is not like this: its loss has many valleys, which is why training it needs care; (b) if the two classes are perfectly separable, the bowl has no bottom (the weights keep growing), and the regularization penalty (C) fixes that by adding its own bowl.

Standardization

Attributes are on very different scales (NordicMart: spend std 685 EUR, tickets std 0.8, recency std 52 days). z-score: x′ = (x − μ)/σ, mean 0 and standard deviation 1; μ and σ are learned from data: training data only, recomputed in each CV round (StandardScaler inside a Pipeline). Computing them on all the data before splitting is leakage, the same rule as the fill-in values of lectures 09 and 10a.

Worked example · what a z-score says

Recency has std 52 days. A customer 52 days above the average has z = +1; one 26 days below has z = −0.5. Tickets have std 0.8: a customer with 1.6 tickets more than average has z = +2. After standardizing, “+1” always means “one std above average”, so the weights are comparable: 0.85 for recency against 0.37 for tickets says recency matters more.

In practice

  • C is the penalty on large weights (regularization): small C = strong penalty, weights shrink towards 0. NordicMart: CV AUC 0.82 for any C from 0.001 to 100.
  • class_weight="balanced" for imbalanced classes. Non-linear boundaries: add new attributes (squares, products). predict_proba gives probabilities; the threshold is our choice.
  • NordicMart: CV AUC 0.82 ± 0.04, test AUC 0.79, precision 0.53, recall 0.19, log loss 0.31: best ranking and best probabilities so far. At threshold 0.5 it raises few alarms (40), precise, low recall; at threshold 0.15: precision 0.30, recall 0.60.

Summary. Pros: simple, fast, interpretable weights; outputs probabilities, usually well calibrated; a strong baseline for any binary problem. Cons: linear in the log-odds (non-linear patterns need new attributes); sensitive to correlated attributes; needs scaling and complete data. Typical uses: credit scoring, medical risk, churn, response to campaigns.

3. More than two classes with binary classifiers

Some classifiers are intrinsically binary (logistic regression, SVM in the next lecture). Two ways to handle C > 2 classes: extend the algorithm, or combine several binary classifiers with a strategy.

Worked example · classes A, B, C, one new record

One-vs-rest: three classifiers “A vs not-A”, “B vs not-B”, “C vs not-C”. For the record they give scores 0.70, 0.40 and 0.20: the highest wins, so the prediction is A.

One-vs-one: three classifiers, one per pair, each trained only on the records of its two classes. A vs B says A, A vs C says A, B vs C says B. Votes: A 2, B 1, C 0, so the prediction is A. With 10 classes it would be 45 small votes instead of 10 big problems.

OVO: more problems, each smaller; attractive when training time grows fast with N. OVR: each problem is imbalanced (with balanced classes, 1 positive to C − 1 negatives). scikit-learn: OneVsRestClassifier, OneVsOneClassifier wrap any binary estimator; SVC uses OVO internally.

4. k-nearest neighbours

kNN keeps all the training data: the model is the training set (instance-based, lazy learning). To classify a new record: compute its distance from every training record, take the k closest (the neighbours), and take the majority vote of their classes. Hyperparameters: k and the distance function.

Worked example · classify a new customer by hand

Six training customers with two standardized attributes (recency, web sessions) and their class (C = churned, S = stayed). New customer q = (0.8, −0.2). Distance = √(Δrecency² + Δweb²); for P2 it is √(0.2² + 0.2²) = 0.28.

Distance functions: Euclidean √Σ(xj − x′j)² (default); Manhattan Σ|xj − x′j|; Minkowski (Σ|xj − x′j|q)1/q includes both; Mahalanobis accounts for scales and correlations; nominal attributes: 0 if equal, 1 if different.

Worked example · scale matters

Customer A against B: spend differs by 100 EUR; A against C: tickets differ by 3. Raw units: d(A,B) = 100 ≫ d(A,C) = 3, as if B were far and C close. Standardized: d(A,B) = 100/685 = 0.15 and d(A,C) = 3/0.78 = 3.8, the opposite verdict. Without scaling, the attribute with the largest numbers decides, so always standardize for kNN. All attributes count, relevant or not.

  • The choice of k (Iris, sepal length and width): k = 1 gives jagged decision regions that follow every point (overfitting); k = 75 gives smooth, coarse regions (underfitting). Choose k as a complexity hyperparameter, by CV. NordicMart: with k = 401 at threshold 0.5 there is no alarm at all.
  • Cost: no training; prediction costs O(N·D) per record (distances to all N records), index structures (KD-tree, ball tree) help; the whole training set stays in memory.
  • Curse of dimensionality: every extra attribute adds a term to the distance, and irrelevant attributes add noise but count as much as the useful ones. With many attributes the nearest and the farthest neighbours end up at almost the same distance, so “the k closest” stops meaning “the k most similar”. Remedies: keep few relevant attributes, or reduce the dimension first. Missing values are not handled: fill them in first. Probabilities are the fraction of the k votes.

5. Comparing the four classifiers on NordicMart

How to read the table
  • k (in “kNN (k = 401)”): the number of neighbours that vote. With k = 401 each prediction is the share of churners among the 401 closest customers. A large k gives smooth probabilities; it was picked by cross-validation among candidate values. Do not confuse it with the k of k-fold CV, the number of folds.
  • t: the decision threshold on the predicted probability of churn: we predict “churn” when the probability is at least t. t = 0.5 is the default; t = 0.15 is the cost-optimal one here (an offer costs €10, a missed churner €100, so it pays to flag even customers with 15% risk).
  • cost at t = 0.15: total cost on the test set = €10 × false positives (wasted offers) + €100 × false negatives (churners missed). Lower is better.
  • κ at t = 0.5: Cohen’s kappa when using the default threshold 0.5. kNN scores 0 because with k = 401 no customer has more than 50% churners among their neighbours, so it never predicts churn at t = 0.5.
  • CV AUC: mean ± std of the AUC over the cross-validation folds (training data); test AUC: the AUC on the test set, measured once.
